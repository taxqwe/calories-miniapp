# AGENTS.md — calories-miniapp

Мини-апы Telegram-бота [taxqwe/caloriesv2](https://github.com/taxqwe/caloriesv2).
Единый источник правил для агентов в этом репозитории.

## 0. Что это за проект

- Чистый HTML + vanilla JS, **без сборки**: нет `package.json`, бандлера, TypeScript.
  Что лежит в репозитории — то и раздаётся.
- Multi-page: каждый раздел — своя папка со своими `index.html` / `script.js` / `style.css`
  (`bmr/`, `edit/`, `history/`, `stats/`, `profile/`, `profile/notifications/`, `other/`).
- Деплой — **GitHub Pages из `main`**, автоматически после мержа, публикация занимает
  1–3 минуты. Ни CI, ни ревью-бота в репозитории нет: `@claude review` тут некому обработать,
  PR-флоу сводится к «push → PR ботом → мерж». Проверять выкладку — запросом нового файла
  (`curl -o /dev/null -w %{http_code}`), а не по времени.
- Бэкенд — `window.CaloriesMiniAppConfig.apiBaseUrl` из `config.js` (прод: `caloriesai.duckdns.org`).
  Все ручки — `POST` с `initData` в теле JSON, не REST GET/PATCH.

## 1. Навигация назад

**Возврат назад — только системной кнопкой Telegram (`tg.BackButton`). Своей кнопки
«назад» в шапке страницы быть не должно.**

Почему: в Telegram-мини-апах системная кнопка — единственный ожидаемый способ вернуться;
вторая кнопка в шапке дублирует её, занимает высоту первого экрана и расходится по
поведению между разделами.

Как правильно на подстранице (образец — `profile/notifications/script.js`):

```js
function goBack() {
  window.location.replace(withLang('../index.html'));
}

if (tg?.BackButton) {
  try {
    tg.BackButton.show();
    tg.BackButton.onClick(goBack);
  } catch (_) { /* noop */ }
}
```

На **верхнеуровневых** вкладках (`history/`, `stats/`, `profile/`) наоборот —
`tg.BackButton.hide()`, чтобы системное «назад» закрывало мини-ап, а не уводило вглубь.

Переходы нижней навигации делаем через `window.location.replace`, чтобы webview не копил
историю вкладок; контентные переходы (например Профиль → `bmr/?mode=edit`) остаются
обычным push, чтобы системное «назад» возвращало на предыдущий экран.

## 2. Обязательные мета-теги против кеша

Каждая страница обязана иметь анти-кеш мета-теги:

```html
<meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate">
<meta http-equiv="Pragma" content="no-cache">
<meta http-equiv="Expires" content="0">
```

Без них Telegram WebView отдаёт устаревший JS при полностью исправном бэкенде
(так уже ловили пустую форму на `bmr/`).

## 3. Язык

- Паритет только **RU + EN**: `ru → ru`, всё остальное → `en`.
- Цепочка источников одна на всех экранах:
  `?lang=` → `profile.locale` из `/api/profile` → `tg.initDataUnsafe.user.language_code` → `en`.
- Статичные лейблы размечаются `data-i18n` (в HTML лежит русский вариант, скрипт свапает
  на английский), динамические строки — в словаре своего модуля.
- При переходах между разделами `?lang=` пробрасывается в ссылки (`withLang`).

## 4. Тема

Общего модуля темы нет: каждая страница красит себя сама функцией `applyTheme`,
выставляя CSS-переменные (`--bg-color`, `--card-bg`, `--accent-color`, `--track-color` и др.)
и подписываясь на `themeChanged`. Новая страница копирует `applyTheme` из соседней —
это осознанное дублирование, а не недосмотр.

## 5. Модули-настройки внутри страницы

Паттерн (см. `profile/notifications/reminders.js`, `digest.js`, `macros.js`):
IIFE слушает событие `profile:loaded`, которое диспатчит скрипт страницы после
`POST /api/profile`, читает своё поле, рисует контрол и сохраняет изменения
оптимистично — с откатом и текстом ошибки при неудачном запросе.

Благодаря этому модуль не привязан к конкретной странице: чтобы перенести карточку
на другой экран, достаточно перенести её разметку и подключить тот же скрипт —
новая страница просто должна диспатчить `profile:loaded`.

## 6. Правила работы

- Ветку заводить от `origin/main` (локальный `main` часто устаревший), работать в отдельном
  `git worktree`.
- Проверять изменения глазами: поднять `python3 -m http.server`, открыть страницу,
  сэмулировать данные через `render(...)` / `profile:loaded`. Автотестов в репозитории нет.
- Не добавлять комментарии без запроса; не коммитить и не мержить без явной просьбы.
